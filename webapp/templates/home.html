What it does

Real AWS integration

Scans real S3 buckets and RDS/PostgreSQL databases — not mock data. Connector config lives in AWS SSM Parameter Store; assessment history lives in DynamoDB.

Dual-layer PII detection

A fast regex heuristic runs alongside Amazon Comprehend’s NLP-based DetectPiiEntities on S3 and document content, so sensitive data does not slip past pattern-matching alone.

Optional LLM judgment

With an Anthropic API key configured, the Claude API samples ingested content to catch sensitive-data nuance, quality issues, and use-case fit that rules cannot.

How it works — 7 stages

  1. 1
    Select AI use case

    Choose what you’re evaluating for — e.g. a customer support agent or a fraud detection model. This decides how the 7 scoring dimensions get weighted later.

  2. 2
    Connect / upload data

    Point at a real S3 bucket, an RDS database, or upload documents directly. Four independent actions: scan S3, run a bucket security check, scan RDS, or assess documents.

  3. 3
    Analyze data estate

    See exactly what was ingested — sources, record counts, and any ingestion errors.

  4. 4
    Calculate AI readiness

    A weighted score across completeness, uniqueness, volume, freshness, privacy risk, security, and AI-content fit.

  5. 5
    Identify critical blockers

    Every finding that needs attention before this data should power an AI system, ranked by severity.

  6. 6
    Generate remediation plan

    Concrete next steps, each with an effort estimate and a projected score gain.

  7. 7
    Show projected readiness

    What your score would look like after applying the suggested fixes — plus the exact minimal payload that would be signed and delivered onward.
